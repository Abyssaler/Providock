## 干净包检查

构建来自 GitHub Actions 干净检出，Tauri 未配置额外 resources 或 externalBin。本机数据库、会话日志、账户配置、签名私钥、密码与本机备份不作为打包输入或发布资产。仓库跟踪的数据样本位于 fixtures，属测试夹具，不作为应用资源打包。

实际检查：

- Mac DMG 校验和有效；只读挂载后版本 2.0.0、标识 io.providock.app、程序架构 arm64。
- Mac 应用内只有 Contents/Info.plist、Contents/MacOS/providock、Contents/Resources/icon.icns、Contents/_CodeSignature/CodeResources 四个文件，没有数据库、日志、账户配置或密钥文件。DMG 顶层为应用、Applications 链接和卷图标。
- Mac 更新归档含上述应用及其目录共 9 项；未含绝对路径、上级路径或链接。解包后的四个应用文件与 DMG 内逐字节一致，两者均通过 codesign --verify --deep --strict。
- Windows NSIS 安装器使用 7-Zip 读取清单并解包：只有 providock.exe、uninstall.exe 与六个标准安装器插件/图像。应用为 PE32+ x86-64，嵌入 FileVersion / ProductVersion 均为 2.0.0.0，没有数据库、日志或账户配置负载。
- 公开资产及解包文件检查未发现本机用户目录字符串或本次签名秘密内容；检查脚本不输出秘密。私钥/密码只用于本地验证及既有 CI Secrets 签名，不进入仓库或发行资产。

上传采用明确的 10 文件白名单：Mac DMG 及 .sig、Providock.app.tar.gz 及 .sig、Windows NSIS 及 .sig、公钥 providock.key.pub、SHA256SUMS.txt、LICENSE.txt、THIRD_PARTY_NOTICES.md。没有上传本机备份、工作目录或验证日志。公钥是公开验签材料。

## Mac 安装与运行

环境：macOS 26.5.2（25F84），Apple Silicon arm64。

1. 在本机保留旧应用和 SQLite 一致性备份，再替换 Applications 中的应用；备份始终留在发行资产目录之外。
2. 安装 v2.0.0 后严格代码签名校验通过，应用进程正常启动。公开 Release 后重新下载 DMG、签名、公钥与校验和，四项 SHA-256 均与原始构建一致；已安装应用的四个文件与正式发行包逐字节相同。
3. 只读检查自有数据库 quick_check 为 ok；安装前所有 event_id 仍存在，数据源及账户行数未减少。未修改 Agent 源日志。
4. 不进行手动同步，间隔超过 60 秒再次只读观察：全部启用源的 last_sync_at 均推进，确认安装后的自动扫描在运行。

本次是安装/启动/数据保留/自动扫描冒烟；不等同完整原生 GUI、真实账户查询或凭据库验收。Kimi/Codex 六项 Token 的独立核对沿用 [自动监测记录](2026-10-11-auto-monitoring.md)，版本准备没有改变采集与调度逻辑。
