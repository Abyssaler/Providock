# 产品需求与范围 v0.1

状态：已确认方向的设计规范；日期：2026-10-11。需求优先级中 P0 为首个稳定版必须满足，P1 为随后增强。研究结果不等于发布支持声明。

## 1. 产品定位

用户需要一处查看“我的电脑用了多少”和“我的各个平台还剩多少”。Providock 是独立监控与账户管理工具，使用者无需将 API Key 注入任何 Agent。它不负责运行模型、切换供应商、编辑 MCP/提示词/技能或管理开发环境。

## 4. 覆盖定义

“支持 Agent”意味着支持指定格式版本的用量读取，不等于平台账单完全一致。每个源独立展示：发现记录的最早时间、最后同步时间、是否有子 Agent、是否有已归档记录、日志是否截断、哪些 Token 字段未知。

cc-switch 支持配置某个 Agent，不代表它能够统计该 Agent。当前研究确认的本地用量导入器为 Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、Pi、MiniMax Code。OpenClaw、Hermes 未发现对应导入器，列为以后研究，不能用“cc-switch 管过它”扩大或混淆本期承诺。Claude Desktop 仅覆盖本地模型映射路径。

平台账户数据可能包含其他机器、其他工具、团队共享消费。因此“账户本周已用”和“本机本周 Token”并排展示，不求和也不相互抵扣。手动关联只能辅助筛选；必须保持关联状态为用户确认/明确标识/未知，不能从模型名猜账户。

## 5. 主要流程

首次启动 → 介绍只读采集和默认隐私范围 → 发现已知目录 → 用户可关闭任何源/添加自定义目录 → 扫描进度和覆盖说明 → 用量总览。拒绝正文查看不影响统计。

添加账户 → 选择平台和区域 → 选择 API 付费/Coding Plan/两者并存 → 展示所需凭据及可查询能力 → Key 保存到本地明文凭据文件 → 只读验证 → 展示快照。普通推理 Key 不具备查询权限时提示所需权限，不能显示“余额为零”。

会话列表 → 查看 Token 分解和来源 → 用户启用正文查看后加载该会话原始消息 → 关闭抽屉释放正文缓存。项目名称/路径允许隐藏，导出前预览字段。

开启网关 → 说明流量范围和推理会经过本进程 → 用户配置目标地址和凭据 → 生成手动配置说明 → 监听本机并采集响应 usage → 关闭后明确不能继续捕获。后台账户轮询不依赖网关。

## 6. 不纳入首版

云同步、多人 SaaS、任意 JavaScript 查询脚本、读取浏览器 Cookie、自动给 Agent 注入 Key、系统 TLS 解密、抓取所有应用网络流量、自动购买或充值、远程设备 SSH 采集、Windows ARM64 原生包、Linux 正式发布和便携版安装器。

## 7. 默认值与可调整事项

拟采用 MIT（沿用仓库许可）、Tauri 2 + Rust + React/TypeScript、SQLite，本地统计默认保留全部历史，账户快照原始频率记录保留 30 天后按日归档（可关闭历史），诊断日志保留 7 天。默认不留存正文。历史清理不删除去重身份；彻底清空采集数据时连同身份和游标清除，明确随后可能重新导入。

macOS 13+、Windows 11 x64 为拟定正式最低基线；Windows 10 22H2 作为需单独验证的兼容目标，不承诺所有 Windows 10 设备。具体适配器版本、账户端点和依赖版本在 P0 验证后固定。无需为这些工程选择重复请求确认；改变用户已确认范围时才需重新讨论。

## 2026-10-12 v2.0.2 用户决定

全局纯黑背景、白色正文和醒目强调色；替换为黑底原创应用图标。趋势各计量分量独立颜色并平滑呈现。macOS 关闭窗口后台常驻，菜单栏展示近期 Agent 用量并提供打开、同步、退出；⌘Q 真正退出。Windows 维持关窗退出。用户明确授权验证后推送 GitHub 并发布 v2.0.2 正式 Release / Latest；既有验证缺口继续如实登记。

用户明确要求修复本地问题、推送并正式发布 v2.0.3、替换当前旧安装，同时增加 GitHub Release 更新通知，后续无需反复卸载。v2.0.3 启动及运行每 6 小时检查正式版，恢复窗口时补查到期更新；设置提供持久化开关和手动检查。应用内提示新版，用户点击后下载，经既有公钥验证签名后安装并重启。退出应用后不检查，不订阅邮件或系统推送；检查不发送本机统计或凭据。更新限定 Apple Silicon Mac 与 Windows x64；同 v2 保留数据，v1 仍手动安装且无自动迁移。
