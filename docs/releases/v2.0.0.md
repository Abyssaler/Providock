# Providock v2.0.0

2026-10-12 · 重建后实现 · 正式 Release

按维护者要求，本版作为 v2.0.0 正式 Release 并设为 Latest 发布，取代未公开发布的 1.1.0-preview.1 候选。本版加入自动用量监测、逐账户到期调度、持久化开关与新的用量总览；发布标记不改变下方列出的验证范围与未完成项。

## 下载与安装

- Apple Silicon Mac：Providock_2.0.0_aarch64.dmg，最低 macOS 13；打开后将 Providock.app 放入 Applications。
- Windows Intel/AMD x64：Providock_2.0.0_x64-setup.exe，为当前用户安装；Windows 11 为拟定支持基线，Windows 10 尚未实机验收。
- SHA256SUMS.txt：安装前可校验下载文件；macOS 使用 shasum -a 256，Windows 使用 Get-FileHash -Algorithm SHA256。
- 更新包采用既有 Tauri/minisign 私钥签名，附公钥与 .sig；Mac 的 Providock.app 另采用完整 ad-hoc 签名，并通过 codesign 严格校验。这不是 Apple Developer ID 公证或 Windows Authenticode 签名。系统可能提示来源未验证；macOS 若阻止打开，可在系统设置的「隐私与安全性」中对这个应用选择「仍要打开」，无需关闭系统整体安全保护。
- Windows 运行依赖 WebView2；安装器按 Tauri NSIS 默认策略处理，离线安装与引导安装尚未实机验收。

本版应用标识为 io.providock.app；旧 v1.0.0 是 com.providock.desktop。需要手动安装，不支持旧版自动更新协议，不提供旧版 latest.json。随附 Providock.app.tar.gz 及签名、Windows 安装器及签名、公钥和 SHA256SUMS.txt；当前应用尚未接入自动更新入口，需手动安装。旧版数据及凭据不会自动迁移，新版使用独立数据域；安装过程不要求清理旧数据或 Agent 日志。正在使用旧版时应先退出旧版，再安装本版。

应用关闭后不继续采集，也不会安装登录启动项或常驻系统服务。

## 本次变化

- Agent 自动同步默认开启：启动一次，随后每轮结束等待 60 秒扫描，跳过未变化文件；没有文件监听，不积压休眠期间的扫描。
- Agent 自动同步与账户自动刷新有各自持久化的可见开关；关闭自动调度会阻止启动首轮，手动刷新仍可使用。
- 账户逐个判断到期：纯 API 余额默认 15 分钟，计划/混合账户 5 分钟，包含正负 10% 抖动；手动查询和失败尝试也纳入截止时间。
- 账户 HTTP 与凭据读取移出数据库锁；同账户请求排重，写回前复核删除、编辑及换凭据。
- 用量页提供 Agent、来源、模型、日期筛选，Token/缓存/费用覆盖率和趋势；显示刷新只读本地数据库，与日志扫描分开。
- 修正 Codex 日期目录漏扫、累计快照与零心跳重复计数、子会话父时间线和已证明重复记录的精确退休。
- 修复新增 Windows 升级回归测试的路径身份构造；保留升级及重扫守恒断言。
- 修复 Mac 应用资源签名完整性；Windows 明确生成 NSIS，避免默认 MSI 对预发布后缀的限制。
- 统一应用版本为 2.0.0；CI 校验安装包/签名齐全，PR 构建不读取发布私钥。

## 验证与适配范围

发布资产必须来自对应版本提交成功的 macOS ARM64 / Windows x64 CI；两端执行前端检查/测试、Rust fmt/Clippy/测试并构建安装包。CI 不等同原生桌面或 Windows 实机验收。

| Agent | 当前证据 |
| --- | --- |
| Claude Code | 合成夹具与扫描接入验证 |
| Codex | 夹具、升级回归及 macOS 本机只读计量快照独立核对 |
| Gemini CLI | 合成夹具与扫描接入验证 |
| Grok Build | 合成夹具与扫描接入验证；活跃/归档双副本去重仍有缺口 |
| OpenCode | 合成夹具与 macOS 本机 V2 数据库只读验证 |
| Pi | 合成夹具与扫描接入验证 |
| MiniMax Code | 合成夹具与扫描接入验证 |
| Kimi Code | 当前 Wire 格式夹具与 macOS 只读计量快照独立核对；旧 Python 协议未接扫描器 |

本机 Kimi/Codex 的全量及当天六项 Token 与独立计算一致，重复扫描不增加计数。数据来自当时快照，活跃日志会增长；该核对不覆盖平台订阅额度。复现方法和数字见 [自动监测验证记录](../research/validation/2026-10-11-auto-monitoring.md)，格式版本及官方依据见 [兼容登记](../research/compatibility-register.md)。

## 已知边界

- 平台余额/计划额度仅做 mock 验证，未做真实凭据联网验收；Codex App Server 账户协议仍为 unsupported 占位。
- Windows 原生安装/运行、macOS 完整原生 GUI 流程、真实系统凭据库、睡眠唤醒和性能基准未完成。
- 通用整源原子升级、截断/未知格式历史保留、旧 DB 升级仍有缺口。升级或测试前应保留已有 Providock 数据副本；用量统计不能替代平台账单。
- Claude Desktop 网关只有 usage 解析层，转发和监听本体未实现；统计导出/清理/价格服务尚未接入 IPC/UI。
- 八源样本验证不代表所有上游版本均兼容；缺失 Token/费用仍显示未知，不补零。

完整开发状态见 [CURRENT_STATUS](../CURRENT_STATUS.md)，本次变更见 [CHANGELOG](../../CHANGELOG.md)，第三方许可见 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)。

## 干净构建

发行资产仅取自 GitHub CI 干净检出的构建；本机数据库、会话日志、账户配置、私钥、密码与本机备份不进入发布包。公钥是公开验签材料。macOS 同时构建 app,dmg，以保留可校验的完整应用和签名更新归档。
