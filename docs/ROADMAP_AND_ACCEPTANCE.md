## 3. 量化目标与实际边界

支持 schema 的 fixture Token 算术误差为 0，重扫/重启幂等误差为 0，预期 duplicate 归并误差为 0。真实平台消费与本机记录可能不完全一致，必须解释其他设备、日志丢失、未落盘、平台折算/延迟等范围，不能用一个不明的“准确率99%”替代验证。

缓存比率采用加权输入分母，标覆盖。请求数仅在已知粒度上提供；Grok 回合不能按记录数冒充请求数。性能目标见架构设计，实测不达标时报告真实结果并处理，不伪造通过。

## 4. 发布检查

所有 Rxx P0 有对应实现和验证；八个本地 Agent 及 Desktop 条件路径已按声明版本验收；账户候选审计完毕，E3/E0 不隐藏成“已接入”；两个正式目标运行证据齐全；无凭据/正文泄漏；迁移/回滚可靠；安装资产签名状态和第三方许可准确。

若某 Agent 当前版本平台本身不支持 Windows，应记录官方平台限制，并验证 Providock 读取其合法导出/既有格式；不能宣称该 Agent 在 Windows 原生运行。Providock 的 Windows 支持和外部 Agent 的平台支持是两个问题。

不通过任一核心准确性/安全/安装门槛时只发明确边界的预览版，更新剩余任务。发布说明必须列版本矩阵和已知缺口，不能把文档或离线原型当已完成应用。
