# ADR 0001：核心边界与技术决策

状态：采纳，依赖版本及适配细节待 P0 验证。日期：2026-10-11。

| 决策 | 理由 | 重新评估条件 |
| --- | --- | --- |
| 本地优先，Tauri 2 / Rust / React / SQLite | 文件、数据库和系统凭据库适合后端统一处理，界面可跨平台复用 | 实际依赖或性能不能满足时，基准比较后换方案 |
| 账户和 Agent 完全分域 | 用户目标是统一监控，不需接入/切换模型 | 用户明确增加配置分发功能，另立需求 |
| 只读日志优先，可选网关默认关闭 | 尽量保留原有工具使用方式；补足 Desktop 条件路径 | 有官方更完整只读源时替换，不静默扩大拦截 |
| 公开官方 / 官方客户端只读接口可用 | 用户接受未公开但有官方依据的能力 | 官方移除或鉴权变化时降级 |
| 仅第三方私有端点暂不接入 | 符合用户选择，避免把逆向能力宣传为官方支持 | 新增官方文档或源码证据 |
| 标准事件账本 + 多证据观察 | 跨源、流式、分叉、复制需要稳定身份与追溯 | 实际不能区分重复/独立请求时修契约 |
| 未知与零、费用与额度分开 | 避免误导余额、缓存命中和订阅支出 | 保持语义，可增强展示 |
| 正文默认不存，可选按需查看 | 满足查看要求，减少敏感数据复制 | 新增全文搜索/归档需求时另做隐私设计 |
| 首版简中、Mac ARM64/Windows x64安装包 | 已确认选择，覆盖常见个人电脑 | 核心稳定后扩展语言/平台/便携版 |
| UI v3.20.4 与功能基线分别固定 | 避免参考设计与当前支持范围混淆 | 用户明确调整视觉方向或更新能力基线 |
| MIT 沿用、历史保留、工作树重新整理 | 用户允许覆盖旧文件，保留恢复与版权依据 | 所有者明确修改许可时审核归属 |

没有选择云端同步、任意脚本查询或系统 TLS 拦截，因为当前目标无需这些能力。未来变更创建新的 ADR，不覆盖历史原因。工程搭建、样本验证或接口审计的未完成项应列任务，不能视为产品范围已经改变。


## 2026-10-11 补充：自动采集与调度控制（D10）

用户明确选择与 cc-switch 相近的运行方式：应用启动自动同步 Agent 日志，随后每 60 秒扫描。此前架构中的文件监听/2 秒去抖/30 秒补扫方案由此替换；八个本地 Agent 的范围和只读边界不变。

采用可唤醒的后台任务：Agent 同步和账户查询独立开关并持久化，关闭时不启用设置轮询；已有任务合并触发，休眠不积压补刷。账户按最近尝试逐个计算余额 15 分钟/计划 5 分钟的截止时间（±10% 抖动），启动首轮也必须检查 enabled。界面的显示刷新只读取本地数据库。这样既能持续监测，也能让用户明确控制后台行为。
